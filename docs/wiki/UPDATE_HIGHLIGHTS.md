# 更新亮点与自愿体验

从 versionCode 487 开始，应用提供安装后离线更新亮点。入口为“设置 → 关于与支持 → 更新 → 本次更新”。

## 增加下一项功能

在 `feature/settings/highlights/UpdateHighlightPolicy.kt` 的 `updateHighlightCatalog` 中追加项目：

- 永久稳定的功能 ID；修改文案不改 ID。
- 首次发布该功能的 versionCode。
- 面向用户的标题、说明。
- 可选的体验操作。没有操作的项目仅用于介绍；新增操作需要同时补充适用条件、预览和确认应用处理。

功能 ID 的处理记录独立于版本号。相同功能不会因后续补丁版本再次邀请。修复类信息放更新日志。版本总览最多展示三项；跨版本升级合并展示，不连续补弹。

## 启动与持久化

- 首次运行建立版本基线。新安装用户不会弹出升级体验邀请。
- 机制首次上线时，旧安装没有历史版本记录，使用 PackageInfo 的 firstInstallTime／lastUpdateTime 辅助判断是否覆盖安装。这是首次接入的兼容判断；重装或系统恢复可能改变安装元数据，不能作为完整版本历史。
- 此后以 DataStore 的版本高水位、待介绍 ID 和已处理 ID 为准。降级不清除记录，重启不重复排队。
- 只在前台首页、首页切换和前后台恢复稳定后延迟展示；跳转、播放、小窗、协议／引导、启动检查更新及崩溃提示期间等待。
- 展示即记录已处理；手动查看同样记住已看，避免返回首页后重复提示。关闭和“保持当前设置”不改变功能设置。
- 记录属于本机安装状态，不加入设置分享的公开键清单。

## 首项：CMF／SPEC_2026

仅在 MD3＋自定义颜色下邀请体验。其他主题或系统颜色来源通过手动入口说明适用条件，不自动修改主题或颜色来源。

点击“预览新配色”显示当前和 CMF 的深浅色比较。预览使用最终配色入口，包含高级覆盖色、纯黑模式和液态玻璃处理。点击“应用新配色”才在一次 DataStore 事务内设置 Standard／Cmf／SPEC_2026，保留其余设置。应用时重新校验预览时的设置快照，发现变化则要求重新预览，避免覆盖其他修改。
